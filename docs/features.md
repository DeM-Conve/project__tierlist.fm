# Features

## Auth & data access
- Google login via Spring Security OAuth2 (session-based, no separate token storage).
- Signed-out landing page (`LoginView`): hero + "Continue with Google", feature summary, and an illustrative tier-board/duel mock (desktop only).
- Scopes: `openid`, `profile`, `https://www.googleapis.com/auth/youtube.force-ssl` (read + write access to playlists).
- `/api/auth/status` reports login state (and the signed-in user's id, so the board cache is only ever shown to its own account) without forcing an OAuth redirect on an unauthenticated request.
- **Board cache**: the playlists list and every opened board's songs are kept on this device (IndexedDB, for up to 7 days), so even a board with hundreds of songs opens instantly on the next visit while the fresh copy loads from YouTube in the background. The fresh copy replaces the board when it lands - unless you've already started editing (a drag, a staged move, a duel result, a sync), which is never overwritten. If YouTube can't be reached the cached board stays up with a small "Showing the copy saved on this device" note and Retry, not an error page. Only playlists and their songs are cached (never settings, duel data or login state); the cache is wiped on logout, never shown to another Google account, dropped when a new build changes its format, and skipped entirely where IndexedDB isn't available (some private windows) - the app then just loads from YouTube as before.

## Playlist naming template (Settings -> Playlist naming)
- One **naming** - a template plus the tier names - defines which playlists are tier playlists, and so which ones are visible in the app at all. **It never renames anything on YouTube** (the user's call: this page only identifies playlists). The template needs `{category}` and `{tier}`; any other `{word}` is a **token of your own**, named by you (e.g. `{my_label}` for names like "[Chill] Rap S") - the app never invents one, and "Detect" keeps the tokens your template already has.
- **Tier names**: for each of the five tiers (best first) and the to-do list, its name **in playlist names** (what `{tier}` matches, exactly; default `S A B C D` + `TODO`, presets `S A B C D` / `A B C D F`, or anything typed - `T1 … TZ`, `(**TODO**)`) and, optionally, what it's **shown as** in the app (rail, chips, board rows, duels, menus, toasts) - e.g. a to-do list named `(**TODO**)` shown as `TODO`. Empty = show the name itself. Names in playlists must differ (case and symbols aside), have a letter/digit and no `{ }`; shown-as names follow the same format but may repeat.
- Generic default `{category} {tier}` ("Rap S"). On first use (or when no tier names are saved yet) the app **auto-detects** the naming that fits the user's existing playlist names (template shape x tier names; most matches, then most specific); Settings also has **Detect from my playlists**.
- **Privacy filter:** only playlists whose title matches the template appear anywhere in the app (Home, sidebar counts, command palette, tier pages - a hidden playlist's `/playlist/<id>` URL redirects home). Home shows "N playlists hidden - not named by your template" (count only, no titles).
- Editor: template presets, click-to-insert tokens, your own tokens, the six tier-name fields (with presets), validation (required tokens, no duplicates, malformed tokens / stray braces, tier-name rules), and a live **Matching playlists** table: every playlist the draft picks up with its tier list, tier and own-token values, plus how many others don't match (count only - they stay hidden). Nothing applies until **Save** (in a bar pinned to the bottom of the page).
- New tier playlists are named by the naming: Home -> **New tier list** (category, a value for each of your own tokens, which tiers, Private/Unlisted/Public) and a board's **Add missing tiers**; both preview the exact names and refuse names the template wouldn't recognise.

## Desktop app (PWA)
- Installable as its own app window (Chrome/Edge: the install icon in the address bar, or menu -> Install Tierlist.fm): launcher/taskbar icon, no browser tabs or toolbar. `vite-plugin-pwa` (manifest + auto-updating service worker; icons generated from `favicon.svg` by `pwa-assets.config.js`). Same origin as the browser tab, so login and the YouTube player work unchanged. The server (Docker) still has to be running.

## Home & playlists
- `/` is **Home**: every board drawn as a mini tier list (tier chip + that tier playlist's cover + a bar sized by its video count), with Open / Duel on each card; a "Now playing" card (with a link back to rate it on its board) while the player is active; then every tier playlist as a card (tier badge + board name). Playlists not following the naming template are never listed.
- Home's filter box and the sidebar's board filter are independent - typing in one never filters the other.
- (Replaced) the old "redirect to the first board on first login" - Home now leads with your boards, which is what that redirect existed for.
- Opening a playlist (Home card, command palette) opens **its tier page** (`/tier/<board>/t/<tier>`) - the same list with the player, shuffle, drag-to-reorder and tier chips; there's no separate read-only playlist view. Old `/playlist/<id>` links redirect there.

## Add songs (bringing a new song in)
- `/add` (sidebar "Add songs", `a` from anywhere, Home's "Add songs" button, command palette): **paste a YouTube / YouTube Music link** - or several at once (one per line / space-separated; watch, youtu.be, music, shorts links). Links only: there is no YouTube search, since a search costs 100 API quota units and a pasted link 1.
- **`Ctrl+V` with a link on any page** (outside a text box) adds it and opens Add songs; anything that isn't a link says so.
- Each added song becomes a card: cover (click / `Enter` to listen in the mini player), song + artist, the **board guessed from the artist** (from boards already loaded this session; else where the last one went - remembered across reloads on this device; `b` / the picker changes it) and big tier buttons: `Shift+1`-`5` (same key as rating anywhere else; plain digits still seek) puts it straight into that tier on YouTube, `t` "Later" = the board's TODO list. `s` skips, `x` removes it from the waiting list, `/` or `a` back to the input. Putting the playing song in a tier plays the next waiting one.
- A song it knows is already in a tier shows "Already in <board> · <tier>" with Open it / Dismiss; one that slips through is auto-deduped when its board is opened.
- "Waiting" strip (click to jump) and an "Added this session" list with per-row Undo; `u` / `Ctrl+Z` / the toast's Undo takes the last one out of its playlist again.
- Errors say what YouTube actually said (daily quota used up, login expired, video not found) instead of a generic failure.

## Sidebar
- **VS Code-style**: a permanent **activity bar** (icon strip) (top to bottom: Home, Jump to, Tier lists, Playlists, Add songs, Duels) - **Tier lists**, **Playlists** and **Duels** each open its view in the panel beside it; clicking the open view's icon closes the panel (`Ctrl+B` / `⌘B` opens / closes it too); icons are muted on the frame and brighten on hover; the open view's icon is full-strength with an accent bar on the strip's left edge - Jump to (`o` / `⌘K`, command palette), Home (`g h`), Add songs (`a`, with a badge counting songs waiting for a tier); at the bottom Keyboard shortcuts (`?`), Settings (`g s`), Log out. Each icon names itself and its key on hover; only the open view is highlighted (as in VS Code).
- **Your own icon order**: drag the activity bar's top icons (Home, Jump to, Tier lists, Playlists, Add songs, Duels) into the order you like, as in VS Code; the order is saved to your account (Postgres `activity_bar_item`, part of your settings row - follows you to every browser, rebased like any setting if two devices change it at once). An icon added later (Duels) joins a saved order at the end of the group. The bottom group (Keyboard shortcuts, Settings, Log out) stays put.
- The **panel** sits straight on the frame beside the strip; drag the edge between it and the page to resize it, 200-520 px, or shut; double-click the edge to reset (react-resizable-panels). The edge shows it can be dragged, like VS Code's sash: a small ⋮ grip in its middle, a resize cursor, and on hover / drag an accent line down its length. **VS Code workbench look**: activity bar, panel, tier rail and mini player are one frame color (`--chrome`, a shade darker than the page in every theme, as in VS Code's Modern themes); the page is a rounded card on it (`--editor`) with a subtle 1px border and the same 8px gap to everything around it. Panel rows use a neutral selection and hover (no accent fill), counts muted; the filter box is VS Code's side-bar input. *Tier lists*: every board with its video total (from playlist item counts - no per-board fetch), a filter box, and an empty-state hint explaining the playlist naming convention. Hold a dragged song over a board to open it. Like a VS Code tree row, hovering a board (or tabbing to it) swaps its count for an inline **Duel** action (straight to that board's duel hub); right-clicking a board opens its menu - **Open board**, **Duel**, **Open tier** › each of its tiers (mantine-contextmenu, defined once as data in `boardMenu.jsx`). *Playlists*: every tier playlist (only ones matching your naming), grouped under its board like a file tree, tier chips in one column, song counts right-aligned, filterable by title or board; one opens its tier page. *Duels* (`Ctrl/Cmd+Shift+D`, VS Code's Run and Debug key): every board, filterable, each row one click from its duel hub (the board you're duelling on highlighted), with quiet meta from the playlists already loaded - its ranked total (to-do songs are never part of duels) - and the same right-click board menu.
- **The panel's layout survives a reload**, per device like VS Code's workbench: shut it (`Ctrl+B`, the open view's icon, or dragging the edge shut) and it stays shut after a refresh - it loads already collapsed, no flash of an open panel - and reopens on the view it was on (Tier lists / Playlists) at its last width. Kept in this browser's localStorage (`settings.js` `DEVICE_UI` for shut/view, react-resizable-panels' `useDefaultLayout` for the width), not your account; with storage unavailable it starts open on Tier lists at the default width. Filters and the narrow-screen drawer aren't kept.
- On narrow screens the whole sidebar is a drawer opened from a burger button (`Ctrl+B` opens / closes it there).

## Tier boards (the tier list)
- Playlists named by your naming (default `<Category> S` … `<Category> D`) are auto-grouped into a per-category tier board (plus an optional `<Category> TODO` list - see below).
- **Whole board on one screen, filling it**: the board measures the height left under the header (above the mini player and footer) and turns it into lines of square album-art tiles. Every tier gets one line, and each spare line goes to the tier hiding the most songs, so big tiers show 2+ lines while small ones stay compact. Whatever still doesn't fit folds into a **"+N show all"** tile. It re-fits live on window resize and when the mini player opens or closes; when even one line per tier (+ TODO) doesn't fit at full size, the tiles shrink (down to 60px) so the whole board, TODO row included, still fits; it only scrolls below that.
- Every tile prints its **song name** (and the artist, on desktop) over the bottom of the cover, so songs sharing one album cover are tellable apart without hovering. Names come from the video title with the "(Official Video)"/"[Lyrics]"/"| Album" noise stripped; "Artist - Song" titles are split into song + artist, otherwise the channel is the artist. Tiles stay square (88px desktop, 64px phone; one-line name on phones).
- Each row's colored label shows the tier, its count (or `matches/total` while searching), **Play this tier** (queues only that tier: "Playing from Rap · T2") and **Shuffle this tier**; the header's Play plays the whole board in tier order; clicking the label or the **"+N show all"** tile opens that tier's full list page. The **chevron column on the right of every row expands it in place** (`⌄`) to every song in the tier (wrapping onto as many lines as it needs; the page scrolls) and folds it back (`⌃`) - always the same spot, level with the row's first line, and pinned while you scroll down a long tier; dimmed when the whole tier already fits. Rows start folded again when you open another board.
- **Rename a board by clicking its name**, in place like an Office document name: the title reads as plain text, a faint outline fades in on hover ("Rename" tooltip), a click edits it right there in the same font with the text selected (the box grows with the text), `Enter` or clicking away saves, `Esc` cancels. A name that can't be used shows why in a red tooltip while you type (and reverts on save). Saving shows every playlist's `old -> new` name (the naming template with the new board name; the TODO list too) and the quota cost, then renames them on YouTube and moves the page to the new board's URL. Blocked while the board has staged changes, when another board already has that name, or when a new name wouldn't read back as this board under the template. A hand-assigned TODO list keeps its assignment.
- Header: board name, "N videos · M tiers", a labelled **tier-mix bar** (segment per tier, hover for count, click to open that tier), and actions: Find (`/`), Duel (`d`), Play (`p`, from the top tier) and Shuffle (`s`, whole board) - each button shows its key, like Find's `/` (keys read from `shortcuts.js`; ignored in text boxes and under the full-screen player, and never the second key of `g d` / `g p` / `g s`).
- **Right-click any song** (board tile or tier-page row) for the same song menu at the cursor, like a native context menu: Play next, Add to queue, **Move to ›** (submenu of tiers), Top / Bottom of the tier, Remove from playlist, Open on YouTube.
- Tiles: click plays, drag moves, hover/focus reveals a play affordance and a `⋯` menu (**Move to** any tier, **Top / Bottom of** this tier, **Open on YouTube**). Full title on hover tooltip.
- The playing video is marked (accent ring + animated equalizer) - only on the board it was opened from.
- Loading rows show Mantine `Skeleton`s; empty rows collapse to a slim drop target (the rows with songs get the room it frees for bigger tiles).
- While the playlists list itself is still loading (right after login / a refresh), the sidebar and the board show skeleton placeholders instead of "0 tier lists" / "0 videos · 0 tiers".
- Vim-style `/` search (also the Find button): `/` opens a find box at the top of the screen (the `/` is part of the box's text - deleting it cancels), each row filters to its matches (and wraps to show all of them), `Enter`/`n` next match, `Shift+Enter`/`N` previous, `Enter` on a single match plays it, `Esc` closes. The active match is scrolled into view and highlighted. Matches song title, channel **and artist name**; every word must match, in any order, ignoring case and accents (`krsna makasam`, `beyonce`).

## TODO list (songs waiting for a tier)
- A board can have a **TODO playlist**: its inbox - save songs there on YouTube, then decide their tier here.
- **How a playlist becomes one** exactly like a tier - its name is your template with the **to-do tier's name** (Tier names -> To-do; default `TODO`, anything you like, e.g. `(**TODO**)`, kept exactly as typed) literally in `{tier}`'s place: with template `[{my_label}] {category} {tier}` and to-do name `(**TODO**)`, `[Chill] Rap (**TODO**)` is Rap's, `[Chill] Rap TODO` is not. Any other playlist can be **assigned to a board by hand** from the board's "Add a to-do list". A board uses one: a hand-assigned list beats a name match, then the first wins. The to-do name and the assignments are saved to your account. The rename job renames to-do lists too (a hand-assigned one takes the template shape), and new to-do lists are created with the same shape.
- On the board it's its own card **under the tiers** (below the last tier; neutral grey, "N to do" in the header); it's excluded from the tier-mix bar, the "N videos" total and duels (it isn't ranked). Every move menu, row chip set, tier tab and the Tier Rail (a small TODO slot at the bottom) include it, so a song can be sent back to TODO too.
- **Triage** (the TODO row's play button on the board, the TODO page's Triage button, or the palette's "Triage the <board> TODO list"; the board header has no Triage button - the TODO row sits right there): plays the TODO songs in order; giving the playing song a tier - player chips / `Shift+1-5`, the rail, a menu, a drag - moves it and starts the next to-do song (songs already rated some other way are skipped). The player shows a "Triage" badge.
- The TODO tier page (`/tier/<board>/t/TODO`) is the list view of the same thing: click a row's tier chip to rate it.
- If a song is both in TODO and a real tier, the rated copy wins and the TODO copy is staged as a duplicate removal.
- A board without one shows **Add a TODO list**: pick an existing playlist with the to-do name that isn't in use (it gets assigned to this board), or create a new one (named by the template with the to-do name in the tier's place, e.g. `Rap TODO`); New tier list can create it too.

## Tier Rail
- A permanent strip of the board's tiers down the right edge of the tier list and tier pages (desktop), with live counts. **Global like the player:** while a song plays, the rail stays on Home, Settings and playlist pages too, showing the playing song's board so you can still rate it there (hidden only on the duel screen). One click does the most useful thing available: **re-rate the playing song** into that tier (when it's from this board; the playing song's art sits on its current tier, with `⇧1-5` hints) → otherwise **open that tier**. The header says which mode it's in ("Rate" / "Tiers").
- Every rail tier is a drop target: drag any tile or row onto it to move it there.
- Layout: the five ranked tiers share the whole height of the rail; under a divider sit two equal slots for what isn't a tier - the board's **TODO** list (if it has one) and **Remove** (red outline like the player's Remove chip; shows how many are staged, and a `Del` hint while a song from this board plays). Both are drop targets; clicking Remove stages the playing song's removal.

## Tier page (full list for big tiers)
- `/tier/<board>/t/<tier>`: a big tier header (Play / Shuffle this tier), tabs for every tier with counts (tabs are drop targets too), and the whole tier as a dense numbered list (rank, cover, title, channel) - virtualized against the page scroll, so a tier of hundreds scrolls and drags smoothly.
- Every row has **one-click tier chips** (current tier filled) and a `⋯` menu (Top / Bottom / Open on YouTube). Click a row to play it.
- Each row shows the song name and artist (same cleaned-up names as the board tiles; full title on hover), its tier chips (click one to move it) and a `⋯` menu. No multi-select - moving is per song (chips, drag, the Tier Rail).
- Filter box (`/` focuses it, `Esc` clears) filters by title, channel or artist (same matching as the board's `/` search); drag rows to reorder (drop position maps back to the real position even while filtered).

## Instant feedback & undo
- Every tier edit - drag, menu, chip, bulk move, rail, player rating, duel result - shows a toast (""Song" → S", "Moved 5 videos → A" - with your tier names) with **Undo**, and `Ctrl/Cmd+Z` undoes the last edit anywhere (up to 50 steps; a bulk move or a whole duel result is one step); `Ctrl/Cmd+Shift+Z` or `Ctrl/Cmd+Y` redoes it ("Redone") until you make a new edit. Undo history resets when the board is reloaded or discarded.

## Drag-and-drop tier editing
- Drag a video from one tier row to another, reorder within a row, drop onto the "+N" tile (appends), onto the Tier Rail, onto a tier tab, or reorder within a tier page's list. Rows tint in their tier color while hovered.
- Drop position is cursor-aware (shown by an accent insertion bar).
- Changes are staged locally first; nothing touches real YouTube data until you sync.

- **Move a song to another board**: drag it and hold it over another board in the sidebar - the entry lights up and after a moment that board opens, still dragging - then drop it on any tier there (same drop targets as a normal drag, drop position kept). It's a staged change like any move: "N changes staged" lists it as `Rock [T2] → Pop [T3]`, and Push adds it to the new playlist and removes it from the old one. The song disappears from its old board and sits in its new tier until then; drag it on to another tier (or board) to re-aim it, `Ctrl+Z` / binning it / "Keep in <board>" takes it back, Discard drops it. Dropping it on the board name alone does nothing. While the open board still has staged moves of its own, the other board doesn't open (a message says to push or discard first - opening a board replaces its draft).

## Sync to YouTube
- **Remove from a playlist** (no Remove row on the board - it's kept out of the tier list): drop a song on the Tier Rail's trash slot (under the tiers; it shows how many are staged), pick **Remove from playlist** in a tile's/row's `⋯` menu, or use the player - a red **Remove** chip at the end of the Rate chips (expanded; same shape as the tier chips, with its `Del` hint), a red trash chip beside the mini bar's tier chips, or the **Delete** key (any player mode, on its board); clicking the rail's trash while a song plays does the same. In a triage session removing the to-do song moves on to the next one. It's staged for deletion. It's a pending change like any move: the toast says "will be removed on push", it's listed as `tier → Removed` in the review (with put-back), Undo/Ctrl+Z/Discard or the review's Put back bring it back. Push deletes that playlist item on YouTube. Removing the top copy of a duplicated song keeps the next copy down (no extra auto-dedupe).
- A floating **staged-changes bar** (bottom-center, above the mini player) appears on every page of a board (tier list, tier page) whenever there are staged changes: "N changes staged · review" / "Discard" / "Push to YouTube ⇧P". Compact on phones. After a push it briefly reports "Synced to YouTube" / "Some changes failed" / "Sync failed".
- **Review changes** (click "N changes staged · review"): a simple list - cover, song and artist, `from → to` tier chips (or "Duplicate removed"), and a **Put back** button per move (undoable); Discard all / Push to YouTube (`Shift+P`) at the bottom. Closes itself once nothing is left.
- Clicking "N changes staged" opens a popup (Mantine `Modal`) itemizing every staged change (video, from tier → to tier, or a duplicate removal - see below).
- "Push to YouTube" calls the backend, which inserts each video into its new playlist before removing it from the old one (so a failed delete never loses a video). Partial failures are reported per item.
- "Discard" reverts the board back to what's actually on YouTube.
- `Shift+P` pushes pending changes (only when there are any) from any board page, same as the button / palette action.

## Duplicate cleanup
- If the same video genuinely exists in two of a board's real tier playlists at once, the lower-tier copy is automatically staged as a pending removal (kept: the highest tier it's in; removed: every other copy) - no manual action needed to flag it.
- It shows up in the pending popup as "Remove from [TODO] · already in [T2]" (the copy going away, then the tier that keeps the song), and the tile is greyed out and tagged "Duplicate" (tooltip: removed on sync) until you sync.
- "Push to YouTube" actually deletes the redundant playlist entry (no bogus re-insert into the same playlist).

## Video focus modal
- Click any thumbnail to open a modal with a real, playable embedded YouTube player (via the official IFrame Player API — not a raw iframe), so playback failures (embedding disabled) are detected and shown with a clear fallback + "Open on YouTube" link.
- Keyboard shortcuts: `Esc` close, `←`/`→` or `h`/`l` (vim-style) to move prev/next, `Shift+1`–`Shift+N` to re-rate the current video (in every player mode - expanded, mini bar or floating - while you're on its board).
- Expanded view: a **YouTube-Music-style queue panel** beside the video, as tall as the player. Header: "Queue · Playing from <board / tier / TODO / Add songs>" and a Shuffle button (shuffles Up next). One scrolling timeline of the **whole** queue (virtualized, so hundreds of songs stay smooth - no "+N more" cut-off): songs already played above (dimmed; the last 200 are kept), the playing song highlighted in place (equalizer on its cover), then **Up next**, one list: the songs you queued (a thin accent bar on the left) followed by the rest of what you started. **Drag any row, by the whole row, anywhere**: reorder Up next, drag a played song back down to hear it again, or drag an upcoming one up into the played list to skip it. **Click a cover (▶ on hover) or double-click a row to play it.** Jumping ahead moves the skipped songs up into the played list, and jumping back puts the later ones back. Hover × removes a row. It auto-scrolls to keep the playing song near the top. Plus on-screen transport controls (prev, back 10s, play/pause, forward 10s, next, volume) and a backdrop glow in the playing song's tier color.
- Queue behaviour (focusSlice): each queue row is its own entry, so the **same song can be queued more than once** (and replays). Play next puts a song at the top of Up next. Add to queue puts it after the songs you've already queued, before the rest of the board. Starting something new (Play, a tier, shuffle, triage, Add songs) **replaces the whole queue**, as YouTube Music does. The **repeat** button cycles off → all (loops the whole queue, in the order it was played) → one (loops the playing song); it's kept across queues and reloads (per device).
- **Play next / Add to queue** (YouTube-Music-style) in every song's "…" menu: Play next puts the song at the top of Up next (right after the playing song), Add to queue after the songs you've already queued (before the rest of the board). It always adds a new entry, so the same song can be queued twice, even the one playing now. With nothing playing, it just starts playing in the mini bar.
- Mini bar (Spotify/YouTube-Music layout, three zones with the transport dead centre): **left** art + title/channel (click to expand); **centre** shuffle up-next · prev · play/pause · next · repeat; a thin accent progress line runs along the bar's top edge (thickens on hover, click to seek); **right** the playing song's tier chips + Remove (click to re-rate), volume, floating corner, expand, stop. The bar is faintly tinted with the playing song's tier color. On phones shuffle/repeat and the floating toggle hide.
- **Volume is a vertical slider everywhere** (mini bar, floating corner, expanded), YouTube-style: click the speaker to mute, hover it for a vertical slider (with the level), mouse-wheel over it nudges ±5. The level and mute are remembered on this device and applied to every new song and after a reload.
- Floating corner: video on top (expand/stop over it), then title, the same centred transport, volume/exit-floating, and the progress line along its bottom edge.
- Navigation walks the whole board in tier order — reaching the end of one tier's videos rolls straight into the next tier instead of stopping.
- The browsing order is frozen the moment the modal opens, so reassigning a video's tier mid-browse never disturbs where "next" takes you.
- When a video finishes playing, it automatically advances to the next one (same tier first, then the next tier).
- "Rate" tier chips under the expanded video show the current tier and re-rate with a click as well as a shortcut.

## Shuffle play
- The board's Shuffle button opens the player on a random video from the board and auto-advances through a shuffled order (a "Shuffle" badge marks the session). Each tier row / tier page also shuffles just that tier. "Play" / "Play from T2" plays in tier order instead.

## Command palette
- `Cmd/Ctrl+K` opens a fuzzy-searchable palette to jump straight to any tier board, tier, or playlist, or trigger contextual actions (start a duel, sync/discard pending changes) without leaving the keyboard. **Duel: <board>** for every board goes to its duel hub from anywhere (also found by "duel", "versus", "compare").
- It also opens every page and Settings tab (**Go to**: Home, Add songs, Settings, Settings → Appearance / Playlist naming / Keyboard shortcuts, Show keyboard shortcuts) and Log out. Each carries search keywords, so `sett`, `theme`, `dark mode`, `todo`, `rename` or `inbox` find the right one.

## Duels (pairwise ranking)
Duels collect evidence; a single duel never moves a song. Every duel feeds a hidden score, and a tier change is only *suggested* once enough results agree - you approve it. All the ranking runs in the backend (`fm.tierlist.duel.engine`); everything is stored in Postgres per account and board, so scores carry over between sessions and devices.
- **Hub** (`/tier/<board>/duel`, the board's Duel button / a Home card / the side panel's Duels view, a board row's Duel action or right-click menu / the palette's "Duel: <board>" / `g d`): board certainty (how sure the model is each song sits in its tier), moves waiting, songs on the fence, a **score map** (every song a dot by score over tier bands at the learned borders; ringed = near a neighbouring tier; hover for the song), session length (Quick 2 / Session 5 / Deep 15 min, remembered on this device), what to sharpen - **Smart mix** (default: whichever duel settles the most among ranked songs) and **Borderlines only**. **To-do songs are never part of duels** (the user's call): no duels, no score, no suggestion - you place them yourself; the old Place TODO mode was removed - and the top moves ready (Move / Keep). `Enter` starts; a session in progress can be resumed.
- **Matchup** (`.../duel/play/<session>`): two real players; clips from 0:30 (30 s each, A then B; each turn after that plays the next part of the song - 1:00-1:30, ... - wrapping to 0:30 at the end; seeking in a player restarts the part where you seeked, it never skips to the other song; Replay clip replays the current part) - `Tab` switches, each keeps its place, `Space` pauses / resumes the clip being heard (pressing play in a side's own player makes it the side being heard); the mini player pauses. **Five-step verdict**: A clearly / A / Too close / B / B clearly (`⇧←` `←` `↓` `→` `⇧→`; "clearly" counts double, a draw still counts). After a verdict: the headline, both songs' score change and what it did ("now 81% T1 - leaning up"), then `Enter` for the next duel (`Space` still only pauses / resumes the clip). "Don't know one of them" (`s`) skips the opponent for the session; `u` undoes. Side panel, as tall as the duel: **why this duel**, the song's **where it belongs** probabilities, this session's verdicts (all of them, scrolling inside the card), then Review suggested moves. **Fits the canvas** on desktop (two columns, lg and up; dock showing, ~1366×768 and up): no page scroll before or after a verdict - the players are full card width until the column runs short, then shrink (16:9); the result replaces the verdict buttons in place (Undo / Next duel), and the hint row under them always holds one line of keys. Phones flow and scroll. Top bar (on the same two columns as the page): certainty gained, duels, time left, End session (`e`).
- **Suggested moves** (`.../duel/moves`): every move the evidence supports (≥85% that it belongs in the new tier or beyond - a move goes as far as that reaches, ≥4 duels, ≥2 opponents near that border); a whole row is one click target (opens its evidence). Layout: the list, then Leaning and Tighten tier order straight under it in the main column (all visible without scrolling past the evidence), beside the evidence panel, which sticks to the top of the page and scrolls inside itself; one column on narrow screens (list, evidence, Leaning, Tighten tier order). Nothing in the panel changes height on hover or after a decision (the score readout line is always there, the Keep / Move pair becomes "Moved to S · Undo" in place). With nothing sure yet there is no list or evidence panel, just an empty state naming the closest song and why, with **Duel more** (to the hub). **Leaning · N not sure yet** is a separate, collapsed, dimmed section under the list - where the duels point but short of the bar, each with what it lacks ("83% · needs 85%", "3 of 4 duels"), never selected; one quiet action: **Move anyway**. To-do songs never get a suggestion, a leaning row, a "Closest" mention or a tier-order entry - you place them. Filter All / Up / Down (counts are the ready moves; it filters the leaning list too, whose header names the filter), **Move** (staged on the board like any edit - toast, Ctrl+Z, push), **Keep** (not suggested again until 5 fresh duels point the same way), **Lock** (never suggested), **Move all at ≥90%**; per song: probabilities, score over its duels (dashed = nearest border; the line under it reads the latest score, or the hovered point), key head-to-heads, play. **Tighten tier order**: every tier starts closed (Leaning too), so the page leads with the suggested moves; open one to see the proposed order first (each song at its new place, "was N", up/down arrows, unmoved songs dimmed), then sort it by score (positions are ranks). Keys (ready moves only, hint row hidden when there are none): `↑↓` browse, `m` move, `x` keep, `l` lock, `p` play.
- **Session summary** (`.../duel/done/<session>`): duels and time, certainty before → after, borders settled / tier orders to tighten, new moves from the session, the biggest upset ("one upset moves scores, never tiers"), pairs marked equal after three "too close" in a row (never asked again). Review moves / Another session / Back to board.
- Algorithms (the design brief's): OpenSkill / Weng-Lin Bradley-Terry rating (implemented in Java, β 2.0) for each duel's odds and score trends; a Davidson-Bradley-Terry refit of the whole log on every analysis (ties, "clearly" = two wins, ~1%/week decay of old duels, uncertainty from the Fisher information, σ grows with time since a song's last duel); tier probabilities from an ordinal probit regression of your current tiers on the scores; pairing by p(1-p) × closeness to a border with Thompson sampling and repeat penalties. To-do songs never enter the engine (no prior, score, pairing or suggestion; old duels with a song now in to-do are dropped from the analysis).

## Settings
- **Appearance** tab (default): pick a **theme** (Tokyo Night, Dracula, Warm charcoal - dark; Paper, Sand, Solarized Light - light; picking one also applies its signature accent), an **accent** (Blue, Violet, Teal, Green, Pink, Red, Orange, Amber - works with any theme; Warm charcoal + Amber is the original look) and a **tier palette** (Vivid, TierMaker classic, Heat). Each option shows a live mini preview, changes apply instantly across the whole app and are saved to your account. All colors come from one file, `frontend/src/themes.js`.
- Dedicated, persistent Settings page (GitHub-style layout: side nav + content), reachable via a gear icon in the sidebar or the `/settings` route.
- **Settings follow your Google account** (Postgres): theme, accent, tier palette, naming template + tier names (+ an unfinished migration), and hand-assigned to-do lists are saved per account and load on any browser you sign into. This browser keeps a cached copy so the right theme shows before the first paint; the account's copy wins once it loads. The first time an account signs in, the settings already on that browser are uploaded, so nothing is lost. A failed save shows a toast and retries on the next change. Two devices editing at once don't clobber each other: if another device saved first, this one fetches its version, keeps its own edits on top and saves again.
- "Keyboard shortcuts" tab: the full shortcut list (same source as the `?` modal).
- **This device remembers your UI preferences** across reloads (browser localStorage, not your account - `settings.js` `DEVICE_UI`): the side panel's shut / open state, view and width; the player's **volume and mute** and **repeat** mode; the duel hub's **session length** (the focus always starts on Smart mix); Add songs' **last board** (the fallback guess for the next song). Bad or missing data, or storage being unavailable, just means the defaults. Not kept: search / filter text, the playing song and queue, modals, selections. On boot the browser's storage is **cleaned**: keys of retired features (the old frontend duel strategy) are removed and cached settings are rewritten with only the fields the app still reads. The settings tab you're on is in the URL (`?tab=`), so a reload keeps it too.

## Routing
- Real, refreshable URLs (React Router): `/`, `/playlist/<id>` (redirects to its tier page), `/tier/<category>`, `/tier/<category>/t/<tier>`, `/tier/<category>/duel` (+ `/duel/play/<session>`, `/duel/moves`, `/duel/done/<session>`), `/settings`. Refreshing directly on any board URL loads it correctly (previously a refresh could leave a board blank until you navigated away and back).
- Refreshing or using browser back/forward lands back on the exact board, playlist, or duel you were on.
- **Up one level, the same everywhere**: every page with a parent shows one crumb at the top, `← <parent>` plus a `g u` hint, and `g u` goes to the same place (one route → parent map, `upLevel.js`): tier page → board → Home; duel hub → board; Suggested moves / a matchup / a session summary → the duel hub (leaving a matchup ends nothing - resume it from the hub); Settings and Add songs → Home. Home has none. Back / forward are the browser's own `Alt+←` up one level (the key shown on every crumb; `g u` too) / `Alt+→` (VS Code's Go Back / Go Forward); nothing in the app takes them (the matchup's arrow verdicts ignore Alt).

## Keyboard shortcuts (full list)
Source of truth is `frontend/src/shortcuts.js` (rendered by the `?` modal and Settings → Keyboard shortcuts) - keep this list in sync with it. The `?` modal lays the sections out in two balanced columns (one when narrow: a phone, the Settings tab), each column one table so every key and description lines up, keys as `Kbd` caps that never clip, scrolling inside the modal.
- Global: `Alt+←` up one level (the key shown on every crumb; `g u` too) / `Alt+→` back / forward (the browser's own, like VS Code's Go Back / Go Forward), `Ctrl/Cmd+K` command palette (VS Code's `Ctrl/Cmd+P`, `Ctrl/Cmd+Shift+P` and `F1` open it too), `?` shortcut help, `Ctrl/Cmd+Z` undo last tier edit, `Ctrl/Cmd+Shift+Z` / `Ctrl/Cmd+Y` redo it (until a new edit, a push, a discard or a reload), `Ctrl/Cmd+B` open / close the panel, `Ctrl/Cmd+Shift+E` show the Tier lists view, `Ctrl/Cmd+Shift+F` show the Playlists view, `Ctrl/Cmd+Shift+D` show the Duels view (all three open the panel - on a phone the drawer - and never close it), `Ctrl/Cmd+,` Settings, `Ctrl+V` paste YouTube link(s) (outside a text box) to add them via Add songs.
- Navigation (Vimium-style, anywhere outside a text box): `f` **link hints** - every visible clickable gets a letter label, type it to click/focus (`Backspace` edits, `Esc`/scroll/click cancels); `o` command palette; `a` Add songs; `g h` Home, `g s` Settings, `g u` up one level on every page (tier page → board → Home, duel pages → hub → board; the crumb at the top of each page shows where), `g b` this board, `g p` playing song's board, `g t` its TODO list, `g d` duel; `[` / `]` previous/next board; `H` / `L` back/forward; `g g` / `G` top/bottom; `Ctrl+d` / `Ctrl+u` half a page down/up (Vim; Ctrl on a Mac too); `g i` focus the page's first text box; `y y` copy the playing song's YouTube link. The key after a `g`/`y` prefix is never also taken by a page shortcut.
- Home: `/` jumps to the "Filter boards & playlists" box (`Esc` leaves it).
- Add songs: `Shift+1`-`5` put in tier 1-5, `t` save to TODO, `Enter` listen, `s` skip, `x` remove, `b` pick board, `/` or `a` the input, `u` / `Ctrl+Z` undo.
- Tier board: `d` duel, `p` play the whole board, `s` shuffle play it, `/` search, `n` / `N` next/previous match, `Enter` play match (or step), `Esc` close search, `Shift+P` push to YouTube (any board page).
- Tier page: `/` filter, `Esc` clear the filter.
- Player: `h` / `l` prev/next track (`←` / `→` too while not expanded), `←`/`→` seek 10s (expanded), `Space` play/pause, `m` mute, `f` fullscreen video (expanded; elsewhere `f` is link hints), `0`-`9` jump to that 10%, `j` minimize (expanded → mini → floating), `k` expand, `Esc` minimize from expanded, `Shift+1`-`9` rate the playing video (any mode, on its board), `Del` remove it from its playlist (staged until push).
- Duel: `Enter` start (hub), `⇧←` / `←` / `↓` / `→` / `⇧→` verdict, `Tab` switch clip, `Space` play/pause, `Enter` next duel (after a verdict), `s` don't know one, `u` undo, `e` end; suggested moves `↑↓` `m` `x` `l` `p`.
